# Copilot CLI acceptance matrix (Copilot only)

Scope: the GitHub Copilot CLI plugin in `.github/plugin/`. Pi behavior is out of scope here. Status words: **tested** = automated check in this repository (fixtures and script runs, not a live Copilot session); **native offline** = the real Copilot CLI with a scripted localhost provider, no hosted model inference; **NOT RUN** = no native session was run for it; **unsupported** = deliberately not provided.

Supported: the latest GitHub Copilot CLI release only, as with Pi; no minimum or older version is claimed. The historical 1.0.98 capture remains in `tests/fixtures/copilot-native-observed.json`. A native offline smoke check on **1.0.107** is recorded below. Hook commands find the plugin root from `COPILOT_PLUGIN_ROOT`, then `PLUGIN_ROOT`, then `CLAUDE_PLUGIN_ROOT`; the configured Bash wrappers resolved the installed root in the native smoke check (the specific environment variable used was not captured). PowerShell integration and hosted-model behavior remain unverified.

| Area | Contract | Status |
| --- | --- | --- |
| Shared module root | Profiles name modules by the canonical repo-relative path `agent/skills/...` on every host (for example `agent/skills/engineering-harness/references/roles/ui-ux-specialist.md`). It resolves under the verified installed shared-source root (the absolute path from the `subagentStart` context, the parent handoff or the advertised installed skill), never the project cwd; a missing root means BLOCKED for that read. No user-home path is baked into a reference, and no files are copied. Profile and registry count are 21. | tested (`tests/copilot-compat-fixes.test.ts`, `tests/portable-module-paths.test.ts`); native offline scout prepend confirmed (1.0.107) |
| `subagentStart` hook | Static, non-authoritative `additionalContext`: installed repository root (`agent/skills/...` joins onto it), host boundary, leaf rule, required handoff fields. Reflects no input (agent name, description). It cannot block, veto or schedule a role. Skills stay lazy-loaded. | script tested; native offline scout injection confirmed (1.0.107) |
| `task` dispatch | Exact namespaced `ns:role` only; unknown role and unavailable model are refused with no substitute. Evidence: one finite capture, historical (1.0.98; `tests/fixtures/copilot-native-observed.json`, checked by `tests/copilot-compat.test.ts`). | finite samples: historical capture and native offline `agent-harness:scout` (1.0.107); other roles NOT RUN |
| `ask_user` | Used only if present in the tool list. Cancel, timeout and missing-answer encodings are unverified (0 invocations in the capture). Any non-exact answer is treated as unanswered (`isApproval` is an internal comparison, imported by no hook). An `ask_user` answer is evidence, not authorization. | comparison tested; live cancel NOT RUN |
| Merge and release | Merge and release are unsupported on Copilot. The host exposes no trusted grant store, approver identity or replay protection, and any approval the agent or shell can write or read is forgeable, so none is accepted. Do them outside the agent session. | unsupported |
| `preToolUse` guard | `release-guard.mjs` is a deny-only, best-effort speed bump for `bash`/`powershell`. It also applies the harness guard's never-run rules from the shared `agent/extensions/subagent/safety-core.ts` (secret files except the redacted `.env` read, unparseable commands, ambiguous paths, curl-to-shell, privilege and persistence, config and git-hook writes, package login and publish), loaded with Node's built-in type stripping; deletes, destructive git, links, process kills, commit, push and PR create stay with Copilot's own approval. Its merge and release rules cover: the PR-merge command, release create/edit/upload/delete, direct merge or release API writes, and tag publication. It never allows or asks, has no env or file override, and exits 2 on malformed shell input. Ordinary commits, feature-branch pushes and PR create/edit/view pass. Tag publication also covers a command-level Git `-c push.followTags=...` option that is effectively true (the last `-c` and the last `--follow-tags`/`--no-follow-tags` win). It reads no persistent Git config or environment, so persistent Git settings and other API or GraphQL mutation forms can evade it; server-side tag rules and least-privilege credentials remain necessary. The session-start and child contexts state that merge and release execution is unsupported, that a native `ask_user` answer cannot mint a Pi delivery grant and that the operator performs those operations outside the session. | script tested; native offline dummy `.env` read denied (1.0.107); native merge/release probes NOT RUN |
| Guard limits | A hook timeout is fail-open; `disableAllHooks` or an untrusted folder disables plugin hooks; shell obfuscation, scripts, other API clients and encoded PowerShell evade pattern matching. The real boundary is user-owned: GitHub branch protection or rulesets, least-privilege tokens, or an admin policy hook. This repository does not install or change them. | documented |
| Read-only roles | 14 registry roles have no native `edit` tool (`read, search, execute`). `execute` is retained, so the shell is unconstrained: this is an instruction and tool contract, not OS isolation. | header projection tested |
| Strict read-only recipe | `--available-tools` / `--excluded-tools` control which tools the model sees (omit `execute` for a truly read-only run). `--deny-tool` write rules do not block writes made through the shell. Sandbox mode is off by default, defaults grant working-directory and profile writes, and a per-command bypass may be allowed; only an operator-configured sandbox with real `readonlyPaths` and `allowBypass: false` approaches isolation. Enabling a sandbox alone is not isolation, and no global setting is changed by this plugin. | native help captured; effect NOT RUN |
| Pi-only controls | Tiers, `modelTier`/`modelSlot`, jobs, grants, pause and Pi extensions are not emulated. | unsupported |

## Native offline smoke check — 1.0.107

Checked on Linux with Node 24.22.1 against candidate `075e7c2300fdb0d98f18dee0ad5bb5459c8cf38b` on PR #90. Installed the npm package `@github/copilot@1.0.107` in a disposable prefix; `copilot --version` reported 1.0.107. The candidate was loaded through `--plugin-dir`; the documented marketplace add/install commands were also run in a separate `COPILOT_HOME`, installing v1.18.0 from the default branch. Normal user configuration was not modified.

For native request/dispatch probes, `COPILOT_OFFLINE=true` and an OpenAI-compatible server on `127.0.0.1` supplied scripted SSE responses. It recorded request bodies, never authentication headers. GitHub/provider credentials were excluded from these offline subprocesses. The server selected exact tool calls; this tests the real CLI's loading, hooks and dispatch plumbing, **not model reasoning, tier routing, task success, or billed savings**. The scripted `STATUS: PASS` is not an independent correctness verdict.

| Probe | Observed result |
| --- | --- |
| Local plugin discovery | `agent-harness` v1.18.0 listed; native debug log reported `loaded=21` agents and `hookCount=3`; skill listing showed eight plugin skills |
| Marketplace installation | `plugin marketplace add alsevilla/agent-harness` and `plugin install agent-harness@alsevilla` succeeded in isolated config; installed plugin listed as v1.18.0 |
| SessionStart context | Both local and marketplace-installed plugin sessions exited 0; recorded model requests contained `Shared Copilot bootstrap from` |
| Named child and subagentStart | Native `task` dispatched exactly `agent-harness:scout`; child request contained `Installed shared-source repository root (absolute): /workspace/agent-harness`; its `view` result returned `FIXTURE_READ_OK`; parent received the four-line handoff |
| Native preToolUse denial | Scripted `bash` attempted to read a harmless dummy `.env` fixture; result was `Denied by preToolUse hook: Blocked by harness safety guard [SECRET]`; the dummy content did not appear in tool results |
| Repository compatibility checks | 84 passed, 0 failed, 1 skipped (PowerShell unavailable); includes the installed-Pi YAML-parser compatibility checks |
| Hosted Copilot inference | BLOCKED: the normal authenticated probe failed with `Authentication failed`; existing GitHub credentials did not provide working Copilot access |

No runtime compatibility defect was found in these sampled paths. This does not validate every role, hosted model availability, `ask_user` cancellation, PowerShell, concurrent execution, or protected GitHub operations. Merge/release denial remains hook-script tested only; no real protected operation was attempted.

## Operator checklist (remaining native/hosted acceptance scenarios)

Common setup: record the CLI version, installed plugin path and candidate fingerprint; use `copilot --plugin-dir <checkout> plugin list` or an actually authorized clean install (a local listing does not prove marketplace install). Record 21 agents, the shared skills inventory, registered hooks and the SessionStart context (it names the installed `agent/AGENTS.md` and `agent/skills/SKILLS.md`). Use an operator-owned disposable fixture under a scratch root, with before/after file manifests and evidence kept outside it. Record each scenario as PASS, FAIL, BLOCKED or NOT RUN with receipts; static tests stay distinct from native execution.

Protected probes are hook-only: pipe documented preToolUse JSON to `release-guard.mjs` and assert one deny object plus reason. An optional native hook check needs an operator-owned inert client stub resolved first in both shells' PATH, no credentials available and outbound network independently blocked; any stub invocation is a test FAILURE, never permission to run the real client. If those preconditions cannot be established, leave native denial NOT RUN. Never run an authenticated or real protected operation (merge, release, tag publication, protected API call) to test denial, including in a scratch checkout with a real remote.

| Scenario | Safe procedure and evidence | Status |
| --- | --- | --- |
| S1 backend-worker module | Parent gives a complete read-only packet and a runtime-verified namespaced dispatch; the child shows its installed repository root and resolves the exact assigned `agent/skills/backend/SKILL.md` from installed files. A missing catalog means explicit BLOCKED, never substituted content. | NOT RUN |
| S2 debugger then worker | Tiny local failing fixture with a focused check. Parent launches the debugger read-only, waits for its terminal report, then launches the exact worker with fixture-only authority; require RED/GREEN and a bounded diff. Leaves launch nobody. | NOT RUN |
| S3 native ask / cancel / missing answer | Confirm `ask_user` is in the tool list; capture a choice, an unchanged freeform answer, a cancellation and a missing-answer case using supported host controls only. Cancel or missing answer halts the dependent step; an answer is never protected-operation authority. Unproducible states stay NOT RUN. | NOT RUN |
| S4 read-only role, no mutation | Run a read-only role (`read, search, execute`) on a bounded inspection task; compare fixture manifests and unexpected paths, logs outside the fixture. This shows behavior only, not filesystem isolation. | NOT RUN |
| S5 ordinary authorized delivery | Local commit and non-force feature push to a local bare fixture; PR create/edit through an inert recording client with body files under the evidence root. No invented grant or prompt; local-only or failed-check packets do not deliver. Real GitHub effects stay NOT RUN. | NOT RUN |
| S6 merge denial | Hook-only: the PR-merge form and its API equivalent, a multiline LF and CRLF case and malformed input. Expect deny/reason, no allow/ask/override; answers, env flags and files change nothing. | NOT RUN |
| S7 release denial | Hook-only, separate receipt from S6: release create/edit/upload/delete, explicit tag push, mirror push, tag-ref API creation. Expect deny/reason with no client run and no reuse of a merge answer. | NOT RUN |
