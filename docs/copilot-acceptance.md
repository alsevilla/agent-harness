# Copilot CLI acceptance matrix (Copilot only)

Scope: the GitHub Copilot CLI plugin in `.github/plugin/`. Pi behavior is out of scope here. Status words: **tested** = automated check in this repository (fixtures and script runs, not a live Copilot session); **NOT RUN** = no live Copilot session was run for it; **unsupported** = deliberately not provided.

Installed CLI used for help evidence: 1.0.98. Hook schemas follow the published GitHub documentation (hooks configuration, custom agents), which may be newer than 1.0.98; live behavior has not been probed.

| Area | Contract | Status |
| --- | --- | --- |
| Shared module root | Profiles name modules by the canonical repo-relative path `agent/skills/...` on every host (for example `agent/skills/engineering-harness/references/roles/ui-ux-specialist.md`). It resolves under the verified installed shared-source root (the absolute path from the `subagentStart` context, the parent handoff or the advertised installed skill), never the project cwd; a missing root means BLOCKED for that read. No user-home path is baked into a reference, and no files are copied. Profile and registry count stay at 20. | tested (`tests/copilot-compat-fixes.test.ts`, `tests/portable-module-paths.test.ts`); live prepend NOT RUN |
| `subagentStart` hook | Static, non-authoritative `additionalContext`: installed repository root (`agent/skills/...` joins onto it), host boundary, leaf rule, required handoff fields. Reflects no input (agent name, description). It cannot block, veto or schedule a role. Skills stay lazy-loaded. | script tested with documented input; live injection NOT RUN |
| `task` dispatch | Exact namespaced `ns:role` only; unknown role and unavailable model are refused with no substitute. Evidence: one finite 1.0.98 capture (`tests/fixtures/copilot-native-observed.json`, replayed by `tests/copilot-native-replay.test.ts`). | finite sample; other roles NOT RUN |
| `ask_user` | Used only if present in the tool list. Cancel, timeout and missing-answer encodings are unverified (0 invocations in the capture). Any non-exact answer is treated as unanswered (`isApproval` is an internal comparison, imported by no hook). An `ask_user` answer is evidence, not authorization. | comparison tested; live cancel NOT RUN |
| Merge and release | Merge and release are unsupported on Copilot. The host exposes no trusted grant store, approver identity or replay protection, and any approval the agent or shell can write or read is forgeable, so none is accepted. Do them outside the agent session. | unsupported |
| `preToolUse` guard | `release-guard.mjs` is a deny-only, best-effort speed bump for `bash`/`powershell`: the PR-merge command, release create/edit/upload/delete, direct merge or release API writes, and tag publication. It never allows or asks, has no env or file override, and exits 2 on malformed shell input. Ordinary commits, feature-branch pushes and PR create/edit/view pass. Tag publication also covers a command-level Git `-c push.followTags=...` option that is effectively true (the last `-c` and the last `--follow-tags`/`--no-follow-tags` win). It reads no persistent Git config or environment, so persistent Git settings and other API or GraphQL mutation forms can evade it; server-side tag rules and least-privilege credentials remain necessary. The session-start and child contexts state that merge and release execution is unsupported, that a native `ask_user` answer cannot mint a Pi delivery grant and that the operator performs those operations outside the session. | script tested; live deny NOT RUN |
| Guard limits | A hook timeout is fail-open; `disableAllHooks` or an untrusted folder disables plugin hooks; shell obfuscation, scripts, other API clients and encoded PowerShell evade pattern matching. The real boundary is user-owned: GitHub branch protection or rulesets, least-privilege tokens, or an admin policy hook. This repository does not install or change them. | documented |
| Read-only roles | 14 registry roles have no native `edit` tool (`read, search, execute`). `execute` is retained, so the shell is unconstrained: this is an instruction and tool contract, not OS isolation. | header projection tested |
| Strict read-only recipe | `--available-tools` / `--excluded-tools` control which tools the model sees (omit `execute` for a truly read-only run). `--deny-tool` write rules do not block writes made through the shell. Sandbox mode is off by default, defaults grant working-directory and profile writes, and a per-command bypass may be allowed; only an operator-configured sandbox with real `readonlyPaths` and `allowBypass: false` approaches isolation. Enabling a sandbox alone is not isolation, and no global setting is changed by this plugin. | native help captured; effect NOT RUN |
| Pi-only controls | Tiers, `modelTier`/`modelSlot`, jobs, grants, pause and Pi extensions are not emulated. | unsupported |

## Operator checklist (Copilot only; every live item is NOT RUN in this change)

Common setup: record the CLI version, installed plugin path and candidate fingerprint; use `copilot --plugin-dir <checkout> plugin list` or an actually authorized clean install (a local listing does not prove marketplace install). Record 20 agents, the shared skills inventory, registered hooks and the SessionStart context (it names the installed `agent/AGENTS.md` and `agent/skills/SKILLS.md`). Use an operator-owned disposable fixture under a scratch root, with before/after file manifests and evidence kept outside it. Record each scenario as PASS, FAIL, BLOCKED or NOT RUN with receipts; static tests stay distinct from native execution.

Protected probes are hook-only: pipe documented preToolUse JSON to `release-guard.mjs` and assert one deny object plus reason. An optional native hook check needs an operator-owned inert client stub resolved first in both shells' PATH, no credentials available and outbound network independently blocked; any stub invocation is a test FAILURE, never permission to run the real client. If those preconditions cannot be established, leave native denial NOT RUN. Never run an authenticated or real protected operation (merge, release, tag publication, protected API call) to test denial, including in a scratch checkout with a real remote.

| Scenario | Safe procedure and evidence | Status |
| --- | --- | --- |
| S1 backend-worker module | Parent gives a complete read-only packet and a runtime-verified namespaced dispatch; the child shows its installed repository root and resolves the exact assigned `agent/skills/backend/SKILL.md` from installed files. A missing catalog means explicit BLOCKED, never substituted content. | NOT RUN |
| S2 debugger then worker | Tiny local failing fixture with a focused check. Parent launches the debugger read-only, waits for its terminal report, then launches the exact worker with fixture-only authority; require RED/GREEN and a bounded diff. Leaves launch nobody. | NOT RUN |
| S3 native ask / cancel / missing answer | Confirm `ask_user` is in the tool list; capture a choice, an unchanged freeform answer, a cancellation and a missing-answer case using supported host controls only. Cancel or missing answer halts the dependent step; an answer is never protected-operation authority. Unproducible states stay NOT RUN. | NOT RUN |
| S4 read-only role, no mutation | Run a read-only role (`read, search, execute`) on a bounded inspection task; compare fixture manifests and unexpected paths, logs outside the fixture. This shows behavior only, not filesystem isolation. | NOT RUN |
| S5 ordinary authorized delivery | Local commit and non-force feature push to a local bare fixture; PR create/edit through an inert recording client with body files under the evidence root. No invented grant or prompt; local-only or failed-check packets do not deliver. Real GitHub effects stay NOT RUN. | NOT RUN |
| S6 merge denial | Hook-only: the PR-merge form and its API equivalent, a multiline LF and CRLF case and malformed input. Expect deny/reason, no allow/ask/override; answers, env flags and files change nothing. | NOT RUN |
| S7 release denial | Hook-only, separate receipt from S6: release create/edit/upload/delete, explicit tag push, mirror push, tag-ref API creation. Expect deny/reason with no client run and no reuse of a merge answer. | NOT RUN |
